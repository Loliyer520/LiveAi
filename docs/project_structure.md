# 项目目录结构说明

本文档定义 LiveAi 当前仓库的推荐目录边界，目标是减少根目录堆积、区分源码与运行态数据，并为后续模块拆分提供稳定落点。

## 1. 根目录保留什么

根目录只保留少量稳定入口和项目级文件：

- `main.py`：主运行入口。
- `switch_preflight.py`：只读预检入口，保留在根目录便于直接执行。
- `README.md` / `ARCHITECTURE.md`：项目说明与架构说明。
- `config.yaml.example`：示例配置。
- `setup.py`：安装或打包元数据。
- `.gitignore`：仓库忽略规则。

不建议把以下内容继续直接放在根目录：

- 运行时状态文件
- 调试输出
- 临时脚本
- 缓存目录
- 随手导出的 JSON / 图片 / 日志

## 2. 源码目录职责

### `core/`

核心运行时与调度逻辑，包含 AI runtime、事件流、状态协调、模型调用编排等核心能力。

适合放入：

- 编排器
- 状态机
- 运行时服务
- 核心领域模型

不适合放入：

- 第三方平台适配细节
- 一次性迁移脚本
- 测试辅助产物

### `pack/`

外部依赖和平台集成层，例如 NapCat、模型 provider、WebUI、JSON 存储、图像服务等。

适合放入：

- 第三方服务接入
- 平台适配器
- 与外部接口直接耦合的实现

### `tool/`

AI 可调用工具的实现与工具箱聚合。

适合放入：

- 工具函数
- 工具注册
- 面向 agent 的工具接口

### `scripts/`

一次性维护脚本、迁移脚本、离线辅助脚本。

适合放入：

- 数据迁移
- 诊断脚本
- 本地开发辅助工具

原则：除少量必须直达的入口外，新脚本默认放进 `scripts/`，不要继续堆在根目录。

建议子目录：

- `scripts/diagnostics/`：人工执行、可能访问真实网络或真实 provider 的诊断脚本

### `test/`

回归测试、行为刻画测试、测试支撑代码与测试资源。

建议：

- 测试输出文件不要长期留在 `test/` 根目录
- 仅测试依赖的静态资源可保留在 `test/fonts/`、`test/support/` 等子目录
- `test/` 默认应保持离线、可被 `unittest discover` 安全扫描；联网诊断脚本应迁到 `scripts/diagnostics/`

## 3. 数据目录职责

### `data/`

`data/` 是运行时可变数据目录，不应混同为源码目录。

当前建议边界如下：

- `data/msgs/`：运行态消息状态、记忆与 token 统计
- `data/prompt/`：提示词模板
- `data/res/`：WebUI 或其他静态资源
- `data/images/`：运行期生成图片与测试导出图片
- `data/file/`：下载或上传的文件缓存
- `data/ipc/`：本地 IPC / sqlite / outbox 等进程间状态
- `data/agent_work/`：子任务或外部工作目录

其中 `data/images/`、`data/file/`、`data/ipc/`、`data/agent_work/` 默认视为运行态产物目录，应忽略版本控制。

## 4. 特殊目录

### `docs/`

放设计说明、迁移记录、分阶段方案和结构文档。只保留可复用文档，不把临时讨论记录混入这里。

### `group/`、`my/`

这两个目录更像本地环境或兼容目录，而不是核心仓库结构的一部分。若后续继续保留，建议：

- 在 README 或专门文档中标注用途
- 避免让核心运行逻辑强依赖这些路径的存在
- 新功能不要继续向这两个目录扩散

## 5. 当前整理规则

从现在开始，建议按下面规则收口：

1. 新的业务代码只放进 `core/`、`pack/`、`tool/`。
2. 新的维护脚本默认放进 `scripts/`。
3. 新的测试资源放进 `test/` 子目录，不直接丢在根目录。
4. 运行时生成物统一进入 `data/` 下的对应子目录。
5. 不在仓库根目录落临时文件、缓存或调试导出。

## 6. 后续可选重构

这次整理先不做大规模搬迁。若后续继续收敛，可以按下面顺序推进：

1. 统一 `group/`、`my/` 的职责，决定保留还是迁出。
2. 评估 `core/` 内按子域拆包，例如 runtime / events / scope / model。
3. 为 `scripts/` 增加 README，列出每个脚本用途。
4. 清理历史测试输出和误生成文件。
